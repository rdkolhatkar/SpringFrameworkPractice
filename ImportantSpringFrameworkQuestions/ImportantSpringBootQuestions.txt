1) What is IOC in Spring Boot? or What is AutoWiring? or What is dependency injection?
Answer:
In Spring Boot IOC stands for Inversion of Control which means that Spring can create objects in the form of Beans.
With IOC there is no need to manually create object using new Keyword. It creates bean in IOC container.
These beans can be injected into field of a class using '@Autowired' annotation

2) What is Spring AOP (Aspect Oriented Programming)? Why Do We Need AOP?
Answer:
Spring AOP is used to separate cross-cutting concerns like logging, security, and transactions from business logic.
It improves code readability, reduces duplication, and makes applications easier to maintain.
AOP works using proxies and intercepts method execution at runtime.
It complements OOP and does not replace it.

3) What is the difference between @RestController and @Controller Annotation in the Spring Boot
Answer:
| Feature               | @Controller                               | @RestController                        |
| --------------------- | ----------------------------------------- | -------------------------------------- |
| Purpose               | Used for traditional MVC web applications | Used for building RESTful web services |

4) Explain Spring Boot Annotations @RestController, @Repository, @Service and @Component including their similarities and differences in tabular format
Answer:
@RestController, @Repository, @Service These three annotations are aliases of @Component annotation.
What does Alias of @Component mean?
In Spring, @Component is the base stereotype annotation that marks a class as a Spring-managed bean.
@Controller / @RestController, @Service, and @Repository are specialized aliases of @Component, meaning:
    -> Internally, they are meta-annotated with @Component
    -> Spring treats them as beans automatically
    -> They add extra semantic meaning and behavior based on application layer
Alias here means:
    -> A specialized name built on top of @Component that provides additional purpose, readability, and framework features without changing core bean behavior.
I) @RestController/@Controller => Are the aliases of @Component. Their additional feature is that they handle HTTP requests.
II) @Service is an alias of @Component. However, there is no additional feature associated with it. Hence we can replace @Service Annotation with @Component
III) @Repository is an alias of @Component. It's additional feature is that it converts checked persistence exceptions into unchecked DataAccessException

6) Explain important Concepts about "@SpringBootApplication" annotation
Answer:
We usually write the "@SpringBootApplication" annotation on a class level. Which means we write this annotation above the class which contains the "main" method.
"@SpringBootApplication" is a combination of three different annotations, which are "@SpringBootConfiguration", "@EnableAutoConfiguration" and "@ComponentScan".
Instead of writing "@SpringBootApplication", if we write "@SpringBootConfiguration", "@EnableAutoConfiguration" and "@ComponentScan" above our main class or application class, then in that case our application will still run without any errors.
-> "@SpringBootConfiguration" : When put this annotation on a class, then this class is considered as a source for bean declarations. In short @SpringBootConfiguration when put on a class makes that class a source for bean declaration.
-> "@ComponentScan" : This annotation scans your project, looks out for declared beans and actually create those beans in IOC container.
-> "@EnableAutoConfiguration" : This annotation instructs spring boot to enable it's auto configuration mechanism.
Spring Boot auto-configuration is a feature that automatically sets up your application based on the libraries you add. It checks the classpath, application properties, and existing beans, then creates required configurations like web server, database, or security by itself. This reduces manual setup and helps beginners start quickly with minimal configuration.

7) Explain Difference between Spring and Spring Boot
Answer:
-> The main difference between Spring and Spring Boot is, Spring boot provides auto configuration. This means Spring boot will create the automatic Configuration classes for us.
   However in traditional Spring Framework we have to create these configuration classes manually.
   Spring boot provides us the 'spring-boot-autoconfigure' jar which contains the code for auto configuration mechanism.
   This 'spring-boot-autoconfigure' jar comes from dependency called 'spring-boot-starter-web'
-> Spring Boot comes with an embedded Tomcat server, which means you do not need to install or configure an external servlet container. By default, Spring Boot packages Tomcat inside the application JAR or WAR. When you run the application using java -jar, the embedded Tomcat starts automatically on the configured port (default is 8080).
   This makes the application self-contained and executable, eliminating the need for deploying it on an external server. You can configure server properties like port, context path, max threads, and access logs directly in application.properties or application.yml.
-> Spring Boot provides support for in-memory database such as H2.
-> Spring Boot automatically manages the dependency versions for us.

8) What is a Dispatcher Servlet? And Explain it's Function and Importance.
Answer:
Dispatcher Servlet is the front controller. It receives all incoming HTTP requests first and then sends them to the right controller to handle them.
-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------
| **Aspect**                      | **Explanation**                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Definition**                  | DispatcherServlet is the **front controller** in Spring MVC that handles all HTTP requests and responses. It acts as a central coordinator for the web application.                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **Package**                     | `org.springframework.web.servlet.DispatcherServlet`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **Function / Responsibilities** | 1. Receives incoming HTTP requests from the client.<br>2. Dispatches requests to the appropriate **Controller** based on URL and mappings.<br>3. Handles view resolution (selects the appropriate JSP, Thymeleaf, or other view templates).<br>4. Integrates with Spring's handler mappings, interceptors, and exception resolvers.<br>5. Provides support for request-to-response workflow (request → controller → service → view → response).                                                                                                                                                             |
| **Importance**                  | 1. **Centralized Request Handling:** All requests go through a single entry point, making routing and configuration easier.<br>2. **Loose Coupling:** Controllers do not need to know about HTTP specifics; DispatcherServlet handles it.<br>3. **Integration:** Works with Spring’s features like validation, data binding, exception handling, and interceptors.<br>4. **Scalability:** Supports multi-controller setups, REST endpoints, and multiple views efficiently.<br>5. **Customizability:** Can be configured with handler mappings, view resolvers, and interceptors to suit application needs. |
| **Flow with Spring MVC**        | Client → DispatcherServlet → HandlerMapping → Controller → ModelAndView → ViewResolver → View → Response to Client                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| **Configuration**               | Usually configured automatically with `@SpringBootApplication` in Spring Boot.<br>In XML-based Spring MVC, it’s defined in `web.xml`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |

What is Spring Boot Actuator?
Answer:
-> It is used for monitoring application. It monitors health of application, checks, how many JVM threads are open, how much disk space is available, how many database instances are live and connected etc.
-> It exposes certain production ready end points to monitor the application.
-> Actuator can be added to the classpath as a dependency
-> 'org.springframework.boot:spring-boot-starter-actuator' this dependency is used for configuring Spring Boot Actuator
